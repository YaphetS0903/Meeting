# 历史测试数据清理工具

本工具用于按明确核实的范围清理历史测试记录，让待办与报表保留真实业务。它不会随应用启动、部署或迁移自动执行。

工具：`backend/app/test_data_cleanup.py`。它不增加网页按钮、后台定时任务或数据库迁移。

## 预览与选择范围

在对应实例的 `backend` 工作目录中运行：

```sh
python -m app.test_data_cleanup preview --output /secure/cleanup-plan.json
```

预览只读数据库并输出会议、任务 ID、名称、数量及阻止清理的关联。默认建议范围仅为标题或直接任务正文去掉首尾空白后，完整等于“测试”“系统测试”“测试会议”“测试任务”“测试任务单”的记录。**标题只是候选线索，执行前必须核对清单中每一场会议及其所有任务。** 其他测试命名须核实后通过 ID 明确加入；不要用包含“测试”的模糊匹配删除，生产测试验收等可能是正式业务。

传入任一 ID 参数后，就只选择明确列出的范围，不再自动补选默认候选：

```sh
python -m app.test_data_cleanup preview \
  --meeting-id CONFIRMED_TEST_MEETING_ID \
  --direct-task-id CONFIRMED_DIRECT_TEST_TASK_ID \
  --output /secure/confirmed-cleanup-plan.json
```

会议任务按所属测试会议整体处理，不允许将会议任务当作直接派发任务单独删除。会议名称相似、正文提到测试、员工姓名相同，均不足以认定为测试数据。此工具不删除账号、部门或整个会议系列。

## 执行流程

执行时，暂停业务写入和后台处理，先备份数据库及附件，在实际实例重新生成清单并逐项核对，不可复用已经执行的清单。若存储目录为符号链接，附件备份须跟随链接保存实际文件；备份及业务行快照应保存在受限运维目录。

```sh
python -m app.test_data_cleanup apply \
  --plan /secure/confirmed-cleanup-plan.json \
  --backup /secure/cleanup-business-rows-before.json \
  --username admin
```

执行要求启用的系统管理员。清单包含所有业务模型表的完整数据摘要；清单或数据库有任何变化，必须重新预览。PostgreSQL 执行事务会锁住这些业务表的写入（等待上限 10 秒）；SQLite 使用立即写事务。先写入独占创建、刷盘完成的业务行备份，再在同一事务清理；失败则整体回滚。备份或清单已存在时拒绝覆盖。

清理行为：

- 删除选中的测试会议、其任务和评定；复用现有会议删除逻辑维护导入来源。
- 删除选中的直接测试任务及责任人、版本、完成申请、周期规则和幂等请求。同步剔除排队提醒中的测试项，混合提醒继续保留真实任务。
- 保留历史发送记录、审计记录、员工资料和磁盘附件。清理操作另记“清理历史测试数据”审计；不发送新的删除通知。
- 若保留会议或任务仍引用待删记录、企业微信原生待办未结束、有通知或导出正在处理，则拒绝执行，先处理关联再重新预览。

## 备份和核验

工具备份涵盖 `Base.metadata` 中所有业务表的列及行，日期以 `$date`、时间以 `$datetime` 标记保存，不包含数据库 DDL、迁移版本表和附件文件。因此运维数据库原生备份及附件备份仍应保留。备份包含员工及账号数据，应保存在限制访问的运维目录；POSIX 下新文件权限为 0600，Windows 下使用目录 ACL。

隔离测试已验证：将业务行备份按现有模型建表顺序恢复到空数据库，按列类型还原日期时间后，所有业务行摘要与删除前一致。实际恢复应使用独立恢复实例、匹配的代码及迁移版本，核验后再切换，避免向仍有业务的数据库直接回灌。

执行后核验选中 ID 均已不存在、员工“我的待办”仅含保留任务、报表不再计入测试评定，且真实任务内容、版本、日期保持原样。核验不创建正式测试任务或发送测试通知。具体执行清单、备份与验证材料由环境负责人在受限目录单独保留。
