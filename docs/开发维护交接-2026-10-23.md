## 已有业务范围

1. 会议系列、部门例会／专项会议、模板编辑、自动保存、预览、发布、修订和接续新建；系列可包含不同会议类型。
2. 上期回顾、本期任务、多人共同任务、完成申请、验证通过／驳回、任务调整和版本追溯；会议编辑申请及授权、管理员或主持人删除保护。
3. Excel／Word 历史导入、原件追溯、按会议整页纠错和确认入库、人员匹配与 AI 辅助建议。AI 不自动确认或替代人工更正。
4. 直接派发、岗位及部门范围校验、任务总览、移交、撤回、每周／每月周期任务和后台生成。
5. 统计、PDF／Excel 导出、鉴权附件、通讯录同步、密码修改、企微工作台自动登录和浏览器扫码登录。
6. 直接任务应用消息、派发人确认创建企微原生待办、持久关联及恢复；事务 outbox、独立监控、告警、备份及隔离恢复演练。

岗位规则：管理员、执行总经理、总经理、董事长可以向全部在用员工派发；部长、厂长、副部长、副厂长、主任、总监按岗位识别，在本部门及子部门范围内派发。具体岗位匹配及排除规则以 `backend/app/services/access.py` 为准。

## 在独立环境启动

需要 Docker 和 Compose v2。自行开发时另需 Python 3.12+、uv、Node.js 22.12+（建议 24）及 npm；Playwright 当前使用本机 Chrome。

### Docker 全栈

在源码根目录执行；只在新环境复制配置，不覆盖现有 `.env`：

```bash
cp .env.example .env
mkdir -p storage monitor-state backups native-todo
```

本地 Docker 在 `.env` 中设 `PUBLIC_URL=http://localhost:8086`。示例数据库账号仅供开发；生产需配置独立 `JWT_SECRET` 和数据库密码。Linux 中将四个持久目录交给 `.env` 的 `APP_UID/APP_GID`（默认 10001）：

```bash
sudo chown -R 10001:10001 storage monitor-state backups native-todo
docker compose -f docker-compose.yml -f docker-compose.app.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.app.yml exec backend \
  python -m app.cli bootstrap --generate-password
curl -f http://localhost:8086/api/health
```

首次创建的管理员为 `admin`，随机密码写入 `storage/local-admin-credentials.txt`；已有管理员不重复初始化。访问 <http://localhost:8086>。生产不使用示例 JWT 或默认数据库密码；旧数据库卷中的密码不会因修改 `.env` 自动改变。

### 前后端开发

开发 `.env` 使用本地数据库、Redis 和 `PUBLIC_URL=http://localhost:5176`，外部集成先保持空值及关闭状态。

```bash
docker compose up -d postgres redis
cd backend
uv sync --frozen --python 3.12
uv run alembic upgrade head
uv run python -m app.cli bootstrap --generate-password
uv run uvicorn app.main:app --host 127.0.0.1 --port 8016
```

另开终端：

```bash
cd frontend
npm ci
npm run dev
```

访问 <http://localhost:5176>；API 文档为 <http://127.0.0.1:8016/docs>。需要后台任务时，另开终端运行 `uv run celery -A app.worker.celery worker --loglevel=INFO`，以及唯一一个 `uv run celery -A app.worker.celery beat --loglevel=INFO --schedule=../storage/celerybeat-dev`。Docker 已运行同一环境的 worker／beat 时，不重复启动。

## 配置与交接边界

| 配置或资料 | 用途与获取方式 |
| --- | --- |
| `.env.example` | 已入库的配置模板；实际 `.env` 从系统负责人安全获取或为新环境单独创建 |
| `DATABASE_URL`、`REDIS_URL`、`JWT_SECRET` | 本地进程连接及认证；Docker 内数据库连接由 Compose 注入 |
| `POSTGRES_PASSWORD`、`APP_UID/GID`、`PUBLIC_URL`、`FRONTEND_BIND/PORT` | Docker 数据库、目录权限及入口配置 |
| `WECOM_CORP_ID/AGENT_ID/SECRET` | 原业务应用，负责登录、应用消息和 JS-SDK |
| `WECOM_DIRECTORY_SECRET` | 独立应用仅补充通讯录手机号、邮箱和派发角色，不能替换业务应用的 Secret |
| `SMTP_*`、`AI_*`、`ALERT_*` | 邮件、OpenAI 兼容 AI 服务和独立告警 |
| `NATIVE_TODO_*`、`WECOM_DIRECT_NOTIFICATIONS_ENABLED` | 待办来源、成员范围、应用待办及直接任务消息开关 |
| 生产数据库、`storage/` | 实际会议、员工、任务和附件；接管旧数据时需另外移交一致性备份 |
| `native-todo/` | 旧机器人授权状态，单独保管；源码仓库和压缩包不包含 |

仓库及交接源码包不包含实际密码、服务器登录资料、原始业务 Excel、数据库、附件、授权缓存、依赖目录或前端编译产物。`backend/app/assets/fonts/` 的字体及许可证、所有迁移、测试和开发文档已包含。现有生产配置及数据由负责人通过安全渠道另行交接，不通过公开仓库分发。

接收 ZIP 后，先用旁边的 `.zip.sha256` 文件核对压缩包，再解压进入 `Meeting/`，执行 `sha256sum -c SOURCE-MANIFEST.sha256`；macOS 可使用 `shasum -a 256 -c`。`HANDOFF.json` 记录准确源码提交，清单覆盖源码和交接元数据，不包含清单自身。ZIP 不带 `.git` 历史；继续提交开发时建议从仓库克隆。

## 企业微信现状与限制

以下是 **2026-10-20 发布记录**，不是本次对生产开关的实时读取：

- 直接任务应用消息及自建应用原生待办开启；会议原生待办关闭，会议通知与邮件仍按原配置。
- 企业微信内派发，由实际派发人通过官方确认窗创建待办；普通浏览器派发，给派发人排确认卡片。责任人无需进入系统手工创建。
- 机器人权限有有效期；新自建应用确认方式无需每周给机器人续权，旧机器人映射仍使用旧通道。
- 官方创建接口没有独立描述参数，补充说明、输出物和详情链接合入待办内容。已创建待办的标题和截止日期不能通过当前服务端接口代改，系统会显示差异。
- 企微完成不直接绕过系统验证关闭任务。回调编号不明、送达不明或恢复失败时先核实已有记录，避免重复创建或重发。
- 工作台静默登录已做真实客户端验证；浏览器扫码的多页面 state 覆盖已修复，最终真实扫码回调仍待用户复核。
- 两条旧无日期测试待办按用户决定暂不处理，不批量重建、删除或补正。

联调入口见 [长期接入方案](企业微信待办长期接入方案-2026-10-13.md)、[联调记录](企业联调与试运行记录.md) 和开发进度最新条目。
