## 1. P1：新建会议首次保存期间继续编辑，新增内容会丢失

**触发方式：** 新建会议，填写标题 A，点击“保存草稿”；在请求返回之前继续把标题改成 B。第一次保存成功后，页面从 `/meetings/new` 切换到新会议的地址，重新读取只包含 A 的服务器草稿，覆盖正在编辑的 B，并将页面标记为已保存。

**复现结果：** 本地浏览器先填写“隔离首次保存的标题”，保存期间改为“保存期间继续输入的新标题”。请求结束后页面重新显示前一个标题，新标题丢失，浏览器没有运行异常。任务内容等同一草稿内的字段也受这段保存逻辑影响。

**原因：** 保存函数虽然检测到请求期间仍有改动，但首次保存后的路由切换会调用 `load()`，覆盖 `draft` 并清除 `dirty`。

**修复方向：** 首次保存成功只更新会议 ID 和版本，保留内存中的未保存内容；地址变化不得重载当前编辑草稿。若仍有改动，应继续保存并保持未保存提示。

代码：[Meeting.vue](/Users/chenny/workspace/codex/会议纪要任务单系统/frontend/src/pages/Meeting.vue:328)。

## 2. P1：历史关联建议会返回无权查看的专项会议内容

**触发方式：** 普通主持人打开自己主持的导入候选，查询“关联同一工作”的建议。对于没有所属部门的专项会议，建议查询会搜索所有无部门的历史专项会议，没有套用该主持人的会议查看权限。

**复现结果：** 隔离主持人甲直接读取主持人乙的专项纪要返回 `403`；甲从自己的候选查询历史建议返回 `200`，其中包含乙的会议标题、事项内容、期限和历史来源信息。

**原因：** 入口仅检查待校验候选的操作权限；底层建议查询没有接收当前用户，也没有过滤 `visible_meetings`。历史关联的确认解析同样需要补充来源会议权限校验。

**修复方向：** 建议搜索和保存／确认关联均检查来源会议权限；无权查看的纪要不进入建议结果。

代码：[historical_links.py](/Users/chenny/workspace/codex/会议纪要任务单系统/backend/app/services/historical_links.py:31)、[main.py](/Users/chenny/workspace/codex/会议纪要任务单系统/backend/app/main.py:1273)。

## 3. P1：旧责任人可以读取换人后的周期任务安排

**触发方式：** 甲负责第一期任务，后续周期改成由乙负责，并更改后续工作内容。甲从自己的旧任务详情打开“周期工作”，仍能读取当前周期规则的完整模板。

**复现结果：** 新一期任务由乙负责，甲读取这条新任务返回 `403`；甲从原任务读取周期规则却返回 `200`，包含乙的新工作内容、责任人和验证人。

**原因：** 读取周期规则只检查当前入口任务的查看权限，随后返回全量 `rule_snapshot`，没有检查后续模板的人员范围或规则维护权限。

**修复方向：** 根据权限裁剪周期规则返回值。普通旧期责任人可以查看自己实例的周期信息；完整后续模板按维护权限或明确的当前人员范围开放。前端同步处理裁剪后的字段。

代码：[extra_api.py](/Users/chenny/workspace/codex/会议纪要任务单系统/backend/app/extra_api.py:108)。

## 4. P2：管理员保存周期安排成功，自动派发时却会停止

**触发方式：** 甲部门部长创建本部门周期任务。管理员维护规则，将后续责任人改成乙部门员工，验证人改成管理员。保存接口接受这项修改，但规则的派发人仍然是甲部门部长。

**复现结果：** 修改返回 `200`；运行到下一期时，后台按甲部长的范围检查，发现乙员工不在范围内，自动暂停规则并记录“派发人权限或责任范围已变化，请重新确认周期规则”。保存成功的安排无法实际派发。

**原因：** 保存时检查的是操作者（管理员）的派发范围，生成时检查的是规则派发人的范围，两者不一致。

**修复方向：** 保存和生成使用一致的规则派发人范围；跨范围维护应当在保存时提示先移交给合适岗位，或提供明确的移交操作，避免接受无法执行的安排。

代码：[recurrence.py](/Users/chenny/workspace/codex/会议纪要任务单系统/backend/app/services/recurrence.py:125)，生成检查在同文件第 174 行附近。

## 5. P2：快速切换任务时，旧响应覆盖最后点击的任务

**触发方式：** 先点击任务甲，请求较慢；再点击任务乙，乙的响应先到并打开详情；甲的响应随后到达，又把详情换回甲。

**复现结果：** 本地浏览器最后点击“隔离任务乙”，先显示乙，随后自动切回“隔离任务甲”。没有浏览器异常。用户可能以为正在操作最后选择的任务。

**原因：** 待办列表请求已有过期响应保护，详情 `open()` 没有。每个返回值都直接写入 `selected`，并清空完成说明、证据和编辑表单。

**修复方向：** 详情请求增加序号或取消机制，只接受最后选择的结果；关闭抽屉时也使尚未完成的详情请求失效。

代码：[Tasks.vue](/Users/chenny/workspace/codex/会议纪要任务单系统/frontend/src/pages/Tasks.vue:57)。
